# データベース管理モジュール仕様書

このドキュメントは、Web Archiveプロジェクトのデータベース管理モジュールの詳細な仕様を定義するものです。このモジュールは、取得したコンテンツを保存し、必要に応じて取得する役割を担います。

## 1. モジュール概要

- **役割**: 取得したWebコンテンツとプレビューファイル名をSQLiteデータベースに保存・取得・削除する。
- **対応実装ファイル**: `src/modules/db_manager.py`

## 2. 機能要件

- **コンテンツ保存**: 取得したHTML, CSS, JavaScript, 画像データ（Base64エンコード）、およびプレビューファイル名をデータベースに保存。
- **ランダムURL生成**: 一意のランダムURLを生成（衝突時のリトライ処理、上限・間隔設定あり）。
- **コンテンツ取得**: ランダムURLを基に保存したコンテンツとプレビューファイル名を取得（画像データはデコード）。
- **コンテンツ削除**: 指定されたランダムURLに対応するデータベースレコードと、関連するプレビュー画像ファイルを削除。
- **データ管理**: 保存日時や元のURLなどのメタデータを保存。

## 3. インターフェース設計

### 3.1 主要関数
- **関数**: `save_content(content: dict) -> str`
  - **説明**: コンテンツ（プレビューファイル名含む）をデータベースに保存し、対応するランダムURLを返す。
  - **引数**:
    - `content`: 辞書形式のコンテンツデータ（`preview_filename` を含む可能性がある）
      ```
      {
        "original_url": "元のURL",
        "html_content": "HTML本文",
        "resources": {
          "css": [{"url": "CSSのURL", "content": "CSS内容"}, ...],
          "js": [{"url": "JSのURL", "content": "JS内容"}, ...],
          "images": [{"url": "画像のURL", "webp_data": "WebP形式のバイナリデータ"}, ...] # 保存前にBase64エンコードされる
        },
        "preview_filename": "プレビューファイル名 (optional)"
      }
      ```
  - **戻り値**:
    - 成功時: 文字列（生成されたランダムURL）
    - 失敗時: 例外をスロー（URL生成リトライ失敗時など）
  - **処理フロー**:
    1. 画像データをBase64エンコード。
    2. ループで一意のランダムURLを生成（衝突時はリトライ、上限あり）。
    3. コンテンツデータ（プレビューファイル名除く）をデータベースに挿入。
    4. プレビューファイル名が存在すれば、対応するレコードを更新。
    5. 生成したランダムURLを返す。

- **関数**: `get_content(random_url: str) -> dict`
  - **説明**: ランダムURLを基に保存したコンテンツとプレビューファイル名を取得。
  - **引数**:
    - `random_url`: 文字列（データベースに保存されたランダムURL）
  - **戻り値**:
    - 成功時: 辞書形式のコンテンツデータ（`preview_filename` を含む）
    - 失敗時: 例外をスロー（該当するデータが見つからない場合）
  - **処理フロー**:
    1. ランダムURLを基にデータベースを検索。
    2. 対応するコンテンツデータとプレビューファイル名を取得。
    3. 画像データをBase64デコード。
    4. 構造化して返す。

- **関数**: `delete_content(random_url: str) -> None`
  - **説明**: 指定されたrandom_urlに対応するアーカイブとプレビューファイルを削除する。
  - **引数**:
    - `random_url`: 文字列（削除対象のランダムURL）
  - **処理フロー**:
    1. データベースからプレビューファイル名を取得。
    2. データベースレコードを削除。
    3. プレビューファイル名が存在し、ファイルが実際に存在すれば削除。

### 3.2 内部関数（参考）
- **関数**: `generate_random_url() -> str`
  - 一意のランダムURLを生成。
- **関数**: `init_database() -> None`
  - データベースとテーブルを初期化（初回起動時のみ）。

### 3.3 データベーススキーマ
- **テーブル**: `archives`
  - `id`: 整数（プライマリキー、自動インクリメント）
  - `random_url`: 文字列（一意のランダムURL、インデックス付き）
  - `original_url`: 文字列（元のURL）
  - `html_content`: テキスト（HTMLコンテンツ）
  - `resources`: テキスト（JSON形式でCSS, JS, Base64エンコード画像データを保存）
  - `preview_filename`: テキスト（プレビュー画像のファイル名、NULL許容）
  - `created_at`: タイムスタンプ（保存日時）

### 3.4 依存モジュールとの連携
- このモジュールは他のモジュールに依存せず、独立して動作。
- Webインターフェースモジュールからコンテンツデータを受け取り、保存や取得を行う。

## 4. 非機能要件
- **パフォーマンス**: SQLiteを使用し、軽量かつ高速なデータアクセスを実現。
- **信頼性**: データの整合性を保つため、トランザクションを使用。
- **エラーハンドリング**: データベース操作の失敗やデータが見つからない場合に適切な例外をスロー。

## 5. 使用ライブラリ
- **sqlite3**: SQLiteデータベースの操作。
- **uuid**: ランダムURLの生成。
- **json**: リソースデータのシリアライズ/デシリアライズ。
- **base64**: 画像データのエンコード/デコード。
- **time**: リトライ時の待機処理。

## 6. テスト方針
- **単体テスト**:
  - `save_content` でデータ（プレビューファイル名含む）が正しく保存されるか。
  - `get_content` で正しいデータ（プレビューファイル名含む、画像デコード済み）が取得できるか。
  - `delete_content` でDBレコードとプレビューファイルが削除されるか（ファイル削除はモック）。
  - ランダムURL生成のリトライ処理が機能するか。
  - 無効なデータや存在しないURLに対するエラーハンドリング。
- **結合テスト**:
  - Webインターフェースモジュールとの連携で、コンテンツの保存と取得が正しく動作するか。
