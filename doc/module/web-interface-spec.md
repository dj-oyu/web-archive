# Webインターフェースモジュール仕様書

このドキュメントは、Web ArchiveプロジェクトのWebインターフェースモジュールの詳細な仕様を定義するものです。このモジュールは、ユーザーとの対話を行い、アーカイブ処理を開始し、結果を表示する役割を担います。

## 1. モジュール概要

- **役割**: ユーザーインターフェースを提供し、アーカイブ、表示、削除、プレビュー更新を管理する。FastAPI、SSEを使用。
- **対応実装ファイル**: `src/modules/web_interface.py`

## 2. 機能要件

- **URL入力フォーム**: ユーザーがURLを入力するフォームを提供。
- **アーカイブ一覧表示**: 保存されたアーカイブをリスト形式またはグリッド形式で表示。
    - 各項目に元のURL、アーカイブ日時、プレビュー画像（生成済みの場合）、削除ボタンを表示。
    - プレビュー生成中はインジケータを表示。
    - 表示形式（リスト/グリッド）の切り替えボタンを提供。
- **アーカイブ処理**: `/archive` エンドポイントでURLを受け取り、コンテンツ取得、DB保存（プレビューファイル名=NULL）、プレビュー生成タスクのキュー追加を行う。
- **コンテンツ閲覧**: `/view/{random_url}` エンドポイントでアーカイブされたHTMLコンテンツを表示。
- **リソース提供**: `/resource/...` エンドポイントでアーカイブされたCSS, JS, 画像リソースを提供。
- **プレビュー画像提供**: `/preview/{preview_filename}` エンドポイントで生成されたプレビュー画像を提供。
- **削除処理**: `/delete/{random_url}` エンドポイントで指定されたアーカイブとプレビュー画像を削除。
- **リアルタイム更新**: `/sse/preview-status` エンドポイントでSSE接続を確立し、プレビュー生成完了時にクライアントに通知してUIを更新。

## 3. インターフェース設計

### 3.1 エンドポイント
- **`/`** (GET)
  - **説明**: ルートページ。URL入力フォームとアーカイブ一覧（プレビュー、削除ボタン、表示切替付き）を表示。
  - **レスポンス**: HTMLページ。
- **`/archive`** (POST)
  - **説明**: URLを受け取り、アーカイブ処理を開始し、プレビュー生成タスクをキューに追加。
  - **リクエストボディ**: `{ "url": "string" }`
  - **レスポンス**: `{ "status": "success", "random_url": "string" }` またはエラー。
- **`/delete/{random_url}`** (DELETE)
  - **説明**: 指定されたアーカイブとプレビュー画像を削除。
  - **パスパラメータ**: `random_url`
  - **レスポンス**: `{ "status": "success", "message": "string" }` またはエラー。
- **`/view/{random_url}`** (GET)
  - **説明**: 保存したコンテンツを表示。
  - **パスパラメータ**: `random_url`
  - **レスポンス**: HTMLコンテンツまたは404エラー。
- **`/resource/{random_url}/{resource_type}/{index}`** (GET)
  - **説明**: 保存されたCSS, JS, 画像リソースを提供。
  - **パスパラメータ**: `random_url`, `resource_type` (`css`, `js`, `image`), `index`
  - **レスポンス**: 対応するリソースのコンテンツまたは404エラー。
- **`/preview/{preview_filename}`** (GET)
  - **説明**: 生成されたプレビュー画像を提供。
  - **パスパラメータ**: `preview_filename`
  - **レスポンス**: JPEG画像または404エラー。
- **`/sse/preview-status`** (GET)
  - **説明**: プレビュー生成完了を通知するServer-Sent Eventsストリーム。
  - **レスポンス**: `text/event-stream` 形式のレスポンス。イベントタイプ `preview_ready`、データはJSON文字列 `{"random_url": "...", "preview_filename": "..."}`。

### 3.2 依存モジュールとの連携
- **コンテンツ取得モジュール**:
  - 関数 `fetch_content(url: str) -> dict` を呼び出し、URLからコンテンツを取得。
- **データベース管理モジュール**:
  - `save_content`: アーカイブ時に呼び出し。
  - `get_content`: 閲覧時、リソース/プレビュー提供時に呼び出し。
  - `delete_content`: 削除時に呼び出し。
  - `init_database`: アプリケーション起動時に呼び出し。
- **コンテンツ公開モジュール**:
  - `render_content`: 閲覧時に呼び出し。
- **プレビュー生成モジュール**:
  - `generate_preview`: プレビューワーカから非同期で呼び出し。
- **非同期キュー (`asyncio.Queue`)**:
  - `preview_queue`: アーカイブ時にプレビュー生成タスクを追加。プレビューワーカが取得。
  - `sse_notification_queue`: プレビューワーカが完了通知を追加。SSEエンドポイントが取得。

## 4. 非機能要件
- **パフォーマンス**: FastAPIの非同期処理を活用し、複数のリクエストを効率的に処理。
- **シンプルさ**: UIは直感的に操作可能。リスト/グリッド表示、削除ボタンを提供。
- **エラーハンドリング**: 各エンドポイントで適切なHTTPステータスコードとエラーメッセージを返す。プレビュー生成失敗時も考慮。
- **リアルタイム性**: SSEを使用してプレビュー完了をリアルタイムに反映。

## 5. テスト方針
- **単体テスト**:
  - 各エンドポイントの正常系・異常系のレスポンス検証。
  - ルートページのHTML生成ロジック（一覧表示、プレビュー/インジケータ表示）の検証。
  - アーカイブ時のキューへのタスク追加（モック使用）。
  - 削除処理の呼び出し確認（モック使用）。
  - SSEエンドポイントの基本的な動作確認（モックまたはテスト用クライアント）。
- **結合テスト**: (今後の課題)
  - アーカイブからプレビュー生成、SSE通知、UI更新までの一連のフロー。
