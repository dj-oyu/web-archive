# コンテンツ取得モジュール仕様書

このドキュメントは、Web Archiveプロジェクトのコンテンツ取得モジュールの詳細な仕様を定義するものです。このモジュールは、指定されたURLからWebコンテンツを取得し、画像を処理する役割を担います。

## 1. モジュール概要

- **役割**: ユーザーが指定したURLからWebコンテンツ（HTML, CSS, JavaScript）を取得し、画像をWebP形式に変換する。
- **対応実装ファイル**: `src/modules/content_fetch.py`

## 2. 機能要件

- **コンテンツ取得**: 指定されたURLからHTML, CSS, JavaScriptを取得。
- **リソース解析**: HTMLから関連リソース（CSS, JavaScript, 画像）のURLを抽出し、取得。
- **画像処理**: 取得した画像をWebP形式に再圧縮して保存。
- **コンテンツ整理**: 取得したコンテンツを構造化し、他のモジュールに渡す。

## 3. インターフェース設計

### 3.1 主要関数
- **関数**: `fetch_content(url: str) -> dict`
  - **説明**: 指定されたURLからコンテンツを取得し、構造化したデータを返す。
  - **引数**:
    - `url`: 文字列（取得対象のURL）
  - **戻り値**:
    - 成功時: 辞書形式のコンテンツデータ
      ```
      {
        "html_content": "HTML本文",
        "resources": {
          "css": [{"url": "CSSのURL", "content": "CSS内容"}, ...],
          "js": [{"url": "JSのURL", "content": "JS内容"}, ...],
          "images": [{"url": "画像のURL", "webp_data": "WebP形式のバイナリデータ"}, ...]
        }
      }
      ```
    - 失敗時: 例外をスロー（呼び出し元でエラーハンドリング）
  - **処理フロー**:
    1. 指定されたURLにリクエストを送信し、HTMLを取得。
    2. HTMLを解析し、関連リソース（CSS, JS, 画像）のURLを抽出。
    3. 各リソースを非同期で取得。
    4. 画像リソースをWebP形式に変換。
    5. 取得したデータを構造化して返す。

### 3.2 内部関数（参考）
- **関数**: `parse_html_resources(html_content: str) -> dict`
  - HTMLからCSS, JS, 画像のURLを抽出。
- **関数**: `fetch_resource(resource_url: str) -> bytes`
  - 指定されたリソースURLからデータを取得。
- **関数**: `convert_to_webp(image_data: bytes) -> bytes`
  - 画像データをWebP形式に変換。

### 3.3 依存モジュールとの連携
- このモジュールは他のモジュールに依存せず、独立して動作。
- 取得したデータはWebインターフェースモジュール経由でデータベース管理モジュールに渡される。

## 4. 非機能要件
- **パフォーマンス**: 非同期処理を使用して、複数のリソースを効率的に取得。
- **エラーハンドリング**: 無効なURLやリソース取得の失敗に対して、適切な例外をスロー。
- **拡張性**: 将来的に他のコンテンツタイプ（動画など）に対応できるよう、柔軟な設計を維持。

## 5. 使用ライブラリ
- **requests**: Webコンテンツの取得。
- **BeautifulSoup**: HTMLの解析とリソースURLの抽出。
- **Pillow**: 画像のWebP形式への変換。

## 6. テスト方針
- **単体テスト**:
  - `fetch_content` 関数の戻り値が正しい構造を持つか。
  - 画像のWebP変換が正しく行われるか。
  - 無効なURLやリソース取得失敗時のエラーハンドリング。
- **結合テスト**:
  - Webインターフェースモジュールから渡されたURLが正しく処理されるか。
