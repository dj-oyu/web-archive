# Web Archive モジュール仕様概要

このドキュメントは、Web Archiveプロジェクトの各モジュールの概要と役割を記述するものです。詳細な仕様については、各モジュールの個別仕様書（`doc/module/*.md`）を参照してください。

## 1. モジュールの構成

システムは以下の主要モジュールで構成されます。モジュールの疎結合を保ち、クラスの継承グラフを単純かつ浅い階層に設計しています。

### 1.1 Webインターフェースモジュール
- **役割**: ユーザーインターフェースを提供し、他のモジュールと連携してアーカイブ、表示、削除、プレビュー更新を行う。FastAPI、SSEを使用。
- **主要機能**:
  - URL入力フォーム、アーカイブ一覧（リスト/グリッド切替、プレビュー、削除ボタン）の表示。
  - アーカイブ処理の開始とプレビュー生成タスクのキューイング。
  - アーカイブコンテンツとプレビュー画像の表示。
  - アーカイブとプレビューの削除。
  - プレビュー完了のリアルタイム通知 (SSE)。
- **詳細仕様**: `doc/module/web-interface-spec.md`

### 1.2 コンテンツ取得モジュール
- **役割**: 指定されたURLからWebコンテンツを取得し、画像を処理する。
- **主要機能**:
  - HTML, CSS, JavaScriptの取得。
  - 画像を抽出し、WebP形式に変換。
- **詳細仕様**: `doc/module/content-fetch-spec.md`

### 1.3 データベース管理モジュール
- **役割**: 取得したコンテンツとプレビューファイル名を保存・取得・削除する。
- **主要機能**:
  - SQLiteデータベースへのコンテンツとプレビューファイル名の保存。
  - ランダムURLの生成（衝突時のリトライ処理付き）。
  - ランダムURLに基づくコンテンツとプレビューファイル名の取得。
  - 指定されたアーカイブと関連プレビューファイルの削除。
- **詳細仕様**: `doc/module/db-manager-spec.md`

### 1.4 コンテンツ公開モジュール
- **役割**: 保存したコンテンツをHTMLとしてレンダリングし、関連リソースを内部URLに書き換える。
- **主要機能**:
  - 保存したHTMLを解析し、CSS, JavaScript, 画像のリンクを `/resource/...` 形式の内部URLに書き換え。
- **詳細仕様**: `doc/module/content-publish-spec.md`

### 1.5 プレビュー生成モジュール
- **役割**: 指定されたURLのスクリーンショットを生成する。
- **主要機能**:
  - Playwrightを使用してヘッドレスブラウザを起動し、指定URLにアクセス。
  - ページのスクリーンショットを指定されたファイル名でJPEG形式で保存。
- **詳細仕様**: `doc/module/preview-generator-spec.md`

## 2. モジュール間の連携概要
- **アーカイブ**: Web I/F -> コンテンツ取得 -> DB管理(保存) -> Web I/F(キュー追加) -> プレビューワーカ -> プレビュー生成 -> DB管理(更新) -> Web I/F(SSE通知) -> クライアントUI更新
- **閲覧**: Web I/F -> DB管理(取得) -> コンテンツ公開 -> Web I/F(表示)
- **削除**: Web I/F -> DB管理(削除) -> Web I/F(応答)

## 3. 開発方針
- 各モジュールは独立してテスト可能であることを重視。
- コードはシンプル、宣言的、純粋関数を志向し、テスタビリティを確保。
- モジュールのインターフェース設計に基づき、単体テストを先に作成し、実装を行う。

このドキュメントは、各モジュールの概要を把握するためのものであり、開発の過程で必要に応じて更新されます。
