# Web Archive システム仕様書

このドキュメントは、Web Archiveプロジェクトのシステム全体の仕様を定義するものです。システムの要件、設計方針、モジュールのインターフェースと連携について記述します。

## 1. システム概要

Web Archiveは、ユーザーが指定したURLのWebコンテンツをアーカイブし、生成したランダムURLで公開する個人用のWebアプリケーションです。以下の機能を主要な要件として実装します。

### 1.1 システムの目的
- ユーザーが任意のURLを入力し、そのコンテンツを保存する。
- 保存するコンテンツはHTML, CSS, JavaScriptを含み、画像はWebP形式に再圧縮して保存する。
- 保存したコンテンツをランダムなURLで公開し、個人使用を目的とするため有効期限は設定しない。

### 1.2 対象ユーザー
- 個人ユーザー（単一ユーザーでの使用を想定）

## 2. システム要件

### 2.1 機能要件
- **URL入力**: ユーザーが任意のURLを入力できるフォームを提供。
- **コンテンツ取得**: 指定されたURLからHTML, CSS, JavaScriptを取得し、画像をWebP形式に変換。
- **コンテンツ保存**: 取得したコンテンツをSQLiteデータベースに保存。
- **ランダムURL生成**: 一意のランダムURLを生成し、保存したコンテンツにマッピング。
- **コンテンツ公開**: 生成したランダムURLで保存したコンテンツを閲覧可能にする。
- **プレビュー生成**: アーカイブ時にページのプレビュー画像（スクリーンショット）を生成し保存。
- **プレビュー表示**: アーカイブ一覧でプレビュー画像を表示。
- **リアルタイム更新**: プレビュー生成完了時にUIをリアルタイムで更新。
- **表示切替**: アーカイブ一覧の表示をリスト形式とグリッド形式で切り替え可能。
- **削除機能**: アーカイブされたコンテンツとプレビュー画像を削除。

### 2.2 非機能要件
- **パフォーマンス**: コンテンツ取得と保存は非同期処理で行い、複数のリクエストを効率的に処理。
- **拡張性**: モジュール設計を疎結合に保ち、将来的な機能追加が容易に可能。
- **シンプルさ**: コードはシンプル、宣言的、純粋関数を志向し、テスタビリティを重視。

## 3. システム設計

### 3.1 アーキテクチャ概要
システムは以下の主要モジュールで構成されます。モジュールの疎結合を保ち、クラスの継承グラフを単純かつ浅い階層に設計します。

- **Webインターフェースモジュール**: ユーザー入力を受け取り、結果を表示。
- **コンテンツ取得モジュール**: URLからコンテンツを取得し、画像を処理。
- **データベース管理モジュール**: コンテンツとプレビュー情報の保存・取得・削除を管理。
- **コンテンツ公開モジュール**: 保存したコンテンツをランダムURLで公開。
- **プレビュー生成モジュール**: Playwrightを使用し、指定URLのスクリーンショットを生成。
- **Webインターフェースモジュール**: ユーザー入力を受け取り、結果を表示。SSEによるリアルタイム更新も担当。

### 3.2 技術スタック
- **Webフレームワーク**: FastAPI（非同期処理とAPI開発に特化）
- **コンテンツ取得**: requests（URLからコンテンツを取得）
- **HTML解析**: beautifulsoup4
- **画像処理**: Pillow（画像をWebPに変換）
- **データベース**: SQLite（軽量なローカルデータベース）
- **ランダムURL生成**: UUID（一意な識別子を生成）
- **プレビュー生成**: Playwright（ヘッドレスブラウザ操作）
- **リアルタイム通知**: sse-starlette (Server-Sent Events)

### 3.3 モジュールのインターフェース設計
各モジュールの主要なインターフェースを以下に定義します。詳細は各モジュールの仕様書（`doc/module/*.md`）を参照。

#### 3.3.1 Webインターフェースモジュール
- **エンドポイント**: `/` (GET) - URL入力フォーム、アーカイブ一覧（プレビュー、削除ボタン、表示切替付き）を表示。
- **エンドポイント**: `/archive` (POST) - URLを受け取り、アーカイブ処理を開始し、プレビュー生成タスクをキューに追加。
- **エンドポイント**: `/view/{random_url}` (GET) - 保存したコンテンツを表示。
- **エンドポイント**: `/delete/{random_url}` (DELETE) - 指定されたアーカイブとプレビューを削除。
- **エンドポイント**: `/resource/{random_url}/{resource_type}/{index}` (GET) - 保存されたCSS, JS, 画像リソースを提供。
- **エンドポイント**: `/preview/{preview_filename}` (GET) - 生成されたプレビュー画像を提供。
- **エンドポイント**: `/sse/preview-status` (GET) - プレビュー生成完了を通知するSSEストリーム。
- **入力**: URL文字列 (POST /archive)
- **出力**: アーカイブ結果、ランダムURL、HTMLページ、リソース、プレビュー画像、SSEイベント

#### 3.3.2 コンテンツ取得モジュール
- **関数**: `fetch_content(url: str) -> dict`
  - 指定URLからHTML, CSS, JavaScriptを取得し、画像をWebPに変換。
  - 戻り値はコンテンツの辞書（HTML本文、関連リソースのリスト）。

#### 3.3.3 データベース管理モジュール
- **関数**: `save_content(content: dict) -> str`
  - コンテンツをSQLiteに保存し、ランダムURLを返す。
- **関数**: `get_content(random_url: str) -> dict`
  - ランダムURLに対応するコンテンツを返す。

#### 3.3.4 コンテンツ公開モジュール
- **関数**: `render_content(content: dict, random_url: str) -> str`
  - 保存したコンテンツをHTMLとしてレンダリングし、関連リソースを適切にリンク。

#### 3.3.5 プレビュー生成モジュール
- **関数**: `generate_preview(url: str, output_filename: str) -> str`
  - 指定URLのスクリーンショットを指定ファイル名で生成し、ファイル名を返す。

### 3.4 モジュール間の連携
- **アーカイブ**:
    1. Web I/FがユーザーからURL受信 (`/archive`)。
    2. Web I/Fがコンテンツ取得モジュール (`fetch_content`) 呼び出し。
    3. Web I/FがDB管理モジュール (`save_content`) 呼び出し（プレビューファイル名はNULLで）。
    4. Web I/Fがプレビュー生成タスクを非同期キューに追加。
    5. Web I/Fがユーザーに成功応答とランダムURLを返す。
    6. プレビューワーカがキューからタスク取得。
    7. プレビューワーカがプレビュー生成モジュール (`generate_preview`) 呼び出し。
    8. プレビューワーカがDB管理モジュール (`UPDATE archives ...`) でプレビューファイル名を更新。
    9. プレビューワーカがSSE通知キューに完了イベントを送信。
    10. Web I/FのSSEエンドポイントがイベントをクライアントに送信。
    11. クライアントJavaScriptがUIを更新。
- **閲覧**:
    1. ユーザーが `/view/{random_url}` にアクセス。
    2. Web I/FがDB管理モジュール (`get_content`) 呼び出し。
    3. Web I/Fがコンテンツ公開モジュール (`render_content`) 呼び出し。
    4. Web I/Fがレンダリング結果を返す。
    5. ブラウザが `/resource/...` や `/preview/...` にアクセスし、Web I/Fが対応するリソース/プレビューを返す。
- **削除**:
    1. ユーザーが削除ボタンをクリック。
    2. クライアントJavaScriptが `/delete/{random_url}` にDELETEリクエスト送信。
    3. Web I/FがDB管理モジュール (`delete_content`) 呼び出し（内部でプレビューファイルも削除）。
    4. Web I/Fが成功応答を返す。
    5. クライアントJavaScriptがページをリロード。

## 4. データ設計
- **テーブル**: `archives`
  - `id`: プライマリキー（自動インクリメント）
  - `random_url`: 一意のランダムURL（文字列、UNIQUE）
  - `original_url`: 元のURL（文字列）
  - `html_content`: HTMLコンテンツ（テキスト）
  - `resources`: 関連リソース（JSON形式でCSS, JS, Base64エンコード画像データを保存）
  - `preview_filename`: プレビュー画像のファイル名（テキスト、NULL許容）
  - `created_at`: 保存日時（タイムスタンプ）
